# JS+Python混合项目 · 项目强制规则
> 本项目为前后混合架构：前端JavaScript，后端Python。所有AI生成代码必须遵守下面全部约束，项目规则优先级高于用户全局规则。

## 1.项目基础信息
- 前端：JavaScript，不随意升级版本，不擅自更换构建工具
- 后端：Python，明确使用项目现有虚拟环境，禁止随意升级pip包版本
- 禁止未经确认新增npm/pip第三方依赖库，新增包必须先说明用途与版本，等待确认后再写入
- 前后端交互严格沿用现有接口契约，不要私自修改请求参数、返回字段结构

## 2.目录结构约束，禁止擅自重构目录
### JS前端目录
- 业务组件、页面、工具函数、静态资源遵循现有目录，不要随意新建根目录业务文件
- 不要擅自打散原有模块结构；新增文件必须匹配项目现有命名与存放位置

### Python后端目录
- 业务接口、数据模型、工具脚本、配置文件沿用现有项目目录
- 配置、密钥、敏感信息**禁止硬编码**，统一读取环境变量；严禁把密钥写死在py/js代码内
- 脚本、服务入口文件位置不要随意改动

> 重要：如果需求需要改动目录结构，先输出改动方案，确认后再修改文件。

## 3.编码规范约束
### JavaScript（前端）
1. 遵循项目现有的 ESLint 规则，输出代码尽量兼容现有代码风格
2. 变量函数小驼峰，组件大驼峰；常量大写
3. 函数避免超长，复杂逻辑拆分工具函数；避免写深度嵌套回调
4. DOM操作、异步请求注意异常捕获，不要遗漏error处理

### Python（后端）
1. 遵循PEP8编码规范；4空格缩进
2. 函数、变量使用蛇形命名 `func_name`；类名大驼峰
3. 必须做好异常捕获，接口、文件IO、网络调用不能裸跑；
4. SQL操作禁止字符串拼接SQL，防止注入风险；优先使用ORM/参数化查询
5. 不要写死文件绝对路径，全部使用相对路径或环境变量读取路径配置
6. 大段业务逻辑拆分成函数，拒绝几百行单文件脚本

## 4.修改代码行为红线（最重要，防止AI乱改老代码）
1. 修改已有代码遵循**最小改动原则，手术式修改**，不做无必要大范围重写原有业务。
2. 改动多文件前，先列出全部改动文件与改动点，确认后再输出代码。
3. 禁止擅自删除已有业务代码；如需删除，先提示确认。
4. 同时涉及JS前端 + Python后端的改动：**分开说明前端改动点、后端改动点**，明确接口变更、入参出参，避免前后端不匹配。
5. 读懂上下文再修改，禁止凭空臆想原有业务逻辑。

## 5.硬性禁止清单
❌ 不私自新增 npm / pip 依赖包
❌ 禁止硬编码密钥、token、账号密码、数据库连接字符串
❌ 禁止SQL字符串拼接；禁止不安全eval类执行代码
❌ 不要超出需求范围额外增加功能
❌ 不擅自修改项目启动脚本、环境配置，改动配置必须提示确认

## 6.输出交互规则
1. 代码修改优先输出diff片段；多文件改动分前端JS、后端Python两部分分开展示
2. 跨前后端修改，先输出思路方案，确认后再写代码
3. 存在多种实现方案，主动对比优劣，不要直接选定一种
4. 遇到需求模糊、歧义点，主动提问确认，不要自行脑补业务
5. 给出代码之后，简要说明风险点与注意事项
